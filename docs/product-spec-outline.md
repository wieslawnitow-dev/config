# План ТЗ: нишевой SEO-лидогенератор с конфигуратором

## Рассмотренные пункты

1. Назначение продукта
   - Продаваемый нишевой SEO-сайт/лидогенератор под изделия на заказ с расчетом по параметрам.

2. Первый тестовый продукт
   - Москитные сетки как первая ниша для проверки структуры, калькулятора и SEO-модели.

3. Будущие ниши
   - Жалюзи, ролеты, ворота, маркизы, плиссе и другие изделия по площади/метражу/параметрам.

4. Модель продажи
   - Клиент получает готовый автономный проект под свою нишу, локацию и бренд.

5. Закрытый полный core продавца
   - Полный универсальный движок, генераторы, все ниши и dev-инструменты остаются у продавца.

6. Экспорт урезанного client-project
   - Из полного core генерируется отдельный проект клиента только с нужными модулями, страницами и конфигурацией.

7. Автономность клиента после передачи
   - Клиент может самостоятельно править свой проект, пересобирать сайт и деплоить на свой хостинг.

8. Отсутствие зависимости от продавца после сдачи
   - У клиента нет зависимости от private package, Supabase продавца, внешнего ядра или серверов продавца.

9. Что получает клиент
   - Урезанный проект, MDX-контент, JSON-конфиги, инструкции, dist/build pipeline и продажную версию для отката.

10. Что клиент не получает
   - Универсальную фабрику, полный core, генераторы всех ниш, dev-инструменты и модули других продуктов.

11. MDX для SEO-контента
   - SEO-страницы, блог, FAQ, локации и коммерческие блоки редактируются через MDX.

12. JSON для цен и конфигурации
   - Цены, настройки калькулятора, сообщения, маркетинговые короткие тексты и параметры услуг хранятся в JSON.

13. Комментарии-инструкции в MDX
   - В MDX-файлах должны быть понятные комментарии, какие зоны можно редактировать и что нельзя ломать.

14. Калькулятор/конфигуратор
   - Визуальный конфигуратор кастомных изделий с размерами, несколькими позициями, опциями и ценой.

15. Формулы расчета
   - Расчет по площади, периметру, погонным метрам, штукам, сервисам и опционально весу.

16. Совместимость опций
   - Двусторонняя фильтрация: тип изделия, объект установки, материал, цвет, крепление, сервис и автоматика.

17. Отключаемые и фиксированные параметры
   - Поля могут быть selectable, fixed или disabled в зависимости от продукта и профиля клиента.

18. Контекст страницы
   - Страница может задавать стартовый контекст калькулятора: продукт, город, объект, тип, полотно, сервис.

19. Сохранение состояния заказа
   - Корзина/позиции заказа могут сохраняться между страницами через browser storage.

20. Static shell и активация React
   - Калькулятор виден как статический shell, а интерактивность включается после действия пользователя.

21. Mobile-first компоновка
   - Открытая форма-конфигуратор без wizard как основного интерфейса, адаптация под mobile/tablet/desktop.

22. Визуальное превью
   - Небольшое схематическое превью изделия, меняющееся от выбранных параметров.

23. SEO-структура сайта
   - Главная, цены, монтаж, виды изделий, объекты установки, локации, блог и перелинковка.

24. Mono-location режим
   - Сайт под одну локацию без лишних city-URL, локация вшивается в контент и SEO.

25. Multi-location режим
   - Сайт под несколько городов с отдельными локальными посадочными и правилами против каннибализации.

26. Главная страница
   - Главная закрывает основной широкий коммерческий интент, если сайт mono-category.

27. Категорийные страницы
   - Страницы видов изделий и объектов установки закрывают уточненные коммерческие интенты.

28. Блог и информационный контент
   - Блог закрывает выбор, замер, цену, монтаж, сравнения, уход и ведет в коммерческие страницы.

29. Перелинковка
   - Коммерческие страницы, блог, цены, монтаж, локации и конфигуратор связываются для SEO и конверсии.

30. Передача продажной версии
   - Финальная версия фиксируется в Git/архиве/теге как исходная точка для отката.

31. Откат к начальной версии
   - Клиент может вернуться к продажной версии через Git tag, архив или backup.

32. Хранение копии продавцом
   - Продавец хранит копию клиентской продажной версии ограниченное время, затем архивирует или удаляет.

33. Границы ответственности
   - После передачи самостоятельные правки клиента выполняются на его ответственность; исправления и новые сборки отдельно.

34. Цена продукта
   - Продукт оценивается не как сайт, а как нишевой SEO-лидогенератор с конфигуратором, контентом и дизайном.

35. Отличие от конструкторов
   - Ценность в нишевой SEO-карте, конфигураторе, контенте, дизайне и готовой структуре лидогенерации.

## Предстоящие пункты для проработки

36. Точная структура client-project
   - Какие папки, файлы, generated-модули, config и content должны быть в проекте клиента.

37. Структура закрытого core продавца
   - Как организовать полный core, чтобы быстро экспортировать урезанные клиентские проекты.

38. Процесс генерации client-project
   - Пошаговый pipeline: профиль клиента, выбор модулей, генерация страниц, сборка, QA, передача.

39. Client profile schema
   - JSON-схема профиля клиента: ниша, страна, язык, город, режим локаций, дизайн, страницы, модули.

40. SEO map generator
   - Правила генерации карты посадочных страниц под mono-location и multi-location.

41. Content package workflow
   - Как готовить купленный/качественный контент и раскладывать его по MDX-файлам.

42. MDX editing rules
   - Какие MDX-блоки клиент может править, какие нельзя, как комментировать и валидировать.

43. JSON config schema
   - Подробная схема JSON-файлов для сайта, цен, калькулятора, сообщений, локаций и маркетинга.

44. Build validation
   - Проверки перед сборкой: битые ссылки, пустые поля, несовместимость, отсутствующие цены, SEO-ошибки.

45. Admin/editor вариант
   - Нужна ли простая админка/файловая CMS поверх MDX/JSON или достаточно инструкций.

46. Build/deploy инструкция клиента
   - Как клиент запускает build и загружает dist на обычный хостинг, FTP, cPanel или static hosting.

47. Hosting compatibility
   - Требования к обычному хостингу: статические файлы, формы, assets, redirects, cache headers.

48. Forms and leads
   - Как принимать заявки без Supabase: PHP, mail, webhook, внешние form-сервисы, Telegram/email.

49. Backup and rollback procedure
   - Практическая инструкция по backup, Git tag, archive, rollback и восстановлению dist.

50. Licensing and sale terms
   - Что клиент получает, что не получает, запрет перепродажи универсальной системы, ответственность за правки.

51. QA checklist before handoff
   - Проверка SEO, sitemap, schema, links, Lighthouse, forms, калькулятора, mobile, контента и деплоя.

52. Post-handoff support model
   - Что входит после передачи, что оплачивается отдельно, как принимать баги и новые правки.

53. Product packages
   - Уровни продажи: базовый, коммерческий, сильный лидогенератор, разные объемы страниц/контента/конфигуратора.

54. First MVP scope
   - Минимальный объем первой версии под москитные сетки, чтобы быстро проверить продукт.

55. Timeline by stages
   - Этапы разработки продукта, генератора, client-project, конфигуратора и первого сайта.
